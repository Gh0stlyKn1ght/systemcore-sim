# Module 03: Java robot code

Robot code should make a decision before a hardware library turns that decision into an electrical action. This module builds that decision boundary as real Java.

## Module outcome

You will convert a drive requirement into typed inputs, a pure decision, a bounded request, a reason code, and nine executable checks. The code runs without WPILib, a Driver Station, a vendor library, or robot hardware.

## Executable artifact

The repository includes [`examples/java-behavior/BehaviorCheck.java`](https://github.com/Gh0stlyKn1ght/systemcore-sim/blob/main/examples/java-behavior/BehaviorCheck.java).

Run it from the repository root:

```bash
npm run test:java
```

Expected result:

```text
PASS: 9 Java behavior checks
```

Java can run a single source file by compiling it in memory and executing its first class. This keeps the first artifact dependency-free while still using real Java. The behavior can later move unchanged into the generated WPILib project.

## Behavior contract

The controller receives mode state, forward input, turn input, and sample age. It returns left and right requests plus a reason.

| Condition | Request | Reason |
|---|---|---|
| Disabled | Neutral | `DISABLED` |
| Enabled outside teleop | Neutral | `WRONG_MODE` |
| Non-finite value or negative age | Neutral | `INVALID_INPUT` |
| Input older than 100 ms | Neutral | `STALE_INPUT` |
| Both axes inside the deadband | Neutral | `DEADBAND` |
| Valid active input | Scaled and bounded | `READY` |

Neutral means both sides request `0.0`. Bounded means neither side can leave `[-1.0, 1.0]`.

## Evidence boundary

Passing these checks proves that the tested Java decision returns the expected values for nine named cases. It does not prove WPILib integration, motor-controller behavior, robot wiring, traction, or electrical safety.
