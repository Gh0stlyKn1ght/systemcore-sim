# Module reflection

This is not a summary assignment. Use your earlier work to show how your mental model changed.

## Part 1: Rebuild the stack from memory

Without opening the previous pages, write the six layers from physical hardware to the team application. Add one responsibility and one example to each.

Then check your model against the module overview and correct it in a different color or with a clearly marked revision.

## Part 2: Correct three statements

Rewrite each statement so it becomes technically defensible.

1. “The roboRIO runs ROS 2.”
2. “If the dashboard shows a number, the sensor is working.”
3. “If robot code is disabled, the system has no electrical energy.”

## Part 3: Evidence boundary

Choose one simulated result from this module. Write:

- what the result supports;
- what it does not support;
- the next stronger test; and
- the new risk introduced by that test.

## Part 4: Short response

Answer in 100–150 words:

> Which layer boundary will prevent the most wasted troubleshooting time, and why?

Use one concrete FRC example. Name the observation that would send you to that layer and the observation that would send you somewhere else.

## Submission check

- Six layers are present and ordered correctly.
- Each correction explains the original misconception.
- Simulation and hardware evidence are not blended together.
- The short response uses a specific system path rather than general language.
