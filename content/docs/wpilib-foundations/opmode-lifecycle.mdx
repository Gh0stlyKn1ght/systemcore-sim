# Trace the OpMode lifecycle

**Essential question:** What exactly happens to one OpMode object as the selection and enable state change?

## Learning targets

By the end of this lesson, you can:

- order every OpMode lifecycle callback;
- distinguish enable/disable transitions from selection changes; and
- choose the correct location for setup, repeated work, stopping, and cleanup.

## Callback contract

| Callback | Frequency | Use it for |
|---|---|---|
| Constructor | Once for each fresh OpMode object | Store dependencies and initialize mode-local state |
| `disabledPeriodic()` | Repeated while this OpMode is selected and disabled | Publish a preview or update disabled-safe selection state |
| `start()` | Once when enabled | Reset the run, start timers, and issue quick initialization |
| `periodic()` | Repeated while enabled | Read inputs, decide, request outputs, and report state |
| `end()` | Once when an active OpMode is disabled | Stop behavior and place requests in a neutral state |
| `close()` | Once before the object is discarded | Release mode-owned resources |

`start()` must return quickly. Blocking it with a long loop or sleep prevents the normal framework loop from running.

## Minimal shape

```java
@Teleop(name = "Lifecycle Trace", group = "Course")
public final class LifecycleTrace extends PeriodicOpMode {
  private final Robot robot;
  private int cycleCount;

  public LifecycleTrace(Robot robot) {
    this.robot = robot;
  }

  @Override
  public void start() {
    cycleCount = 0;
  }

  @Override
  public void periodic() {
    cycleCount++;
  }

  @Override
  public void end() {
    robot.drivetrain().stop();
  }

  @Override
  public void close() {}
}
```

Imports and reporting code are omitted so the lifecycle remains visible.

## Three traces to know

### Select, then run

```text
constructor
disabledPeriodic ...
start
periodic ...
end
close
```

### Change selection without enabling

```text
old disabledPeriodic ...
old close
new constructor
new disabledPeriodic ...
```

### Run the same named mode again

After the earlier object is closed, the framework constructs a fresh object for the next selection. Do not rely on an old OpMode instance to preserve state across runs.

## Independent diagnosis

A student resets `cycleCount` in `periodic()`, opens a log file in every `disabledPeriodic()` call, and leaves the drivetrain request unchanged in `end()`.

For each line, name the callback that should own the work and explain the failure caused by the original location.
