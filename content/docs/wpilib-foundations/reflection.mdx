# Reflection and correction

Complete this page after the lifecycle lab and before the module quiz.

## 42-minute plan

| Minutes | Work |
|---|---|
| 0–8 | Reconstruct the lifecycle from memory. |
| 8–18 | Compare the reconstruction with the recorded trace. |
| 18–30 | Correct two misconceptions with evidence. |
| 30–38 | Explain the model to a partner. |
| 38–42 | Commit the revised explanation. |

## Reconstruct without notes

Draw or write the callback order for:

1. selecting an OpMode while disabled;
2. enabling it;
3. disabling it;
4. selecting a different OpMode while disabled; and
5. returning to the first named OpMode.

Mark which transitions create a fresh object.

## Correct two statements

For each statement, write a correction and cite one observation from your lab.

1. “Disabled means no code is running.”
2. “The same OpMode object stays alive for the entire robot program.”
3. “A clean build proves the callbacks run in the expected order.”
4. “Every repeated task belongs in the selected OpMode.”
5. “Changing frameworks is automatically an upgrade.”

## Final explanation

Write 150 to 250 words that answers:

> How does WPILib own control flow while the team owns robot behavior?

Your explanation must use these terms accurately: **selection**, **enabled**, **periodic**, **fresh instance**, **shared resource**, and **neutral request**.
