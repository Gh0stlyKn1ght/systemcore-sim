# Module 06: NetworkTables and telemetry

**Status:** Complete first edition.

NetworkTables moves typed values between robot code, dashboards, tools, and coprocessors. Telemetry is the engineering decision about **what those values mean**, when they were observed, and whether they are still safe to use.

A visible value is not automatically a trustworthy value.

## Module outcomes

By the end of this module, students can:

- explain topics, publishers, subscribers, and entries;
- distinguish existence, type, freshness, validity, and authority;
- design telemetry that explains a decision instead of flooding a dashboard;
- attach observation time and fallback reason to control-relevant data; and
- choose between live NetworkTables data and recorded data logs.

## Evidence chain

| Field | Question it answers | Example |
|---|---|---|
| Observation | What did the system receive or measure? | `drive/input/forward = 0.62` |
| Observation time | When was it produced? | `drive/input/observedAtMicros` |
| Validity | Did the producer's checks pass? | `drive/input/valid = true` |
| Decision | What did the behavior choose? | `drive/decision/state = "COMMAND"` |
| Request | What output did software ask for? | `drive/request/left = 0.58` |
| Reason | Why did it choose that result? | `drive/decision/reason = "bounded input"` |

This chain establishes what software knew and requested. It does not prove that a motor moved or that a mechanism was safe.
