# Module 07: desktop simulation

**Status:** Complete first edition.

Desktop simulation is a controlled experiment. It runs robot behavior against modeled inputs, outputs, sensors, and physics without claiming that real wiring or mechanisms behave the same way.

## Module outcomes

- explain what desktop simulation replaces and what it does not;
- run a deterministic 20 ms update loop;
- connect drive requests to modeled velocity, distance, and heading;
- inspect telemetry from a repeatable run; and
- inject reversed-encoder and frozen-heading faults;
- preserve baseline, failure, and recovery evidence.

## Two simulation layers

| Layer | Purpose | Command |
|---|---|---|
| Repository model | Hardware-free, deterministic behavior and fault checks | `npm run test:simulation` |
| WPILib desktop simulation | Generated robot project, HAL simulation, GUI, modeled devices, and WPILib integration | matching Gradle simulation command from the installed release |

The repository model is executable now. The WPILib layer must use the exact selected 2027 prerelease and generated project because package names and templates are still changing.
