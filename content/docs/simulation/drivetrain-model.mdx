# Differential drivetrain model

**Essential question:** How do two side velocities determine forward motion and rotation?

## Learning targets

- connect normalized requests to target side velocity;
- calculate distance and heading changes; and
- name the model's simplifying assumptions.

## 42-minute plan

| Minutes | Work |
|---|---|
| 0–5 | Predict equal, opposite, and unequal side requests. |
| 5–17 | Trace target velocity and first-order response. |
| 17–29 | Calculate one 20 ms state update. |
| 29–38 | Compare straight and turning scenarios. |
| 38–42 | Document one model limitation. |

## Repository model

The executable model uses normalized left and right requests in `[-1, 1]`.

```text
target velocity = request × maximum speed
new velocity = old velocity + response × (target - old)
distance += velocity × dt
heading rate = (right velocity - left velocity) / track width
heading += heading rate × dt
```

The first-order response prevents velocity from changing instantly. It is a teaching model, not a measured motor-and-gearbox plant.

## Scenario predictions

| Left | Right | Expected modeled motion |
|---:|---:|---|
| `+0.6` | `+0.6` | Forward with near-zero heading change |
| `-0.6` | `-0.6` | Reverse with near-zero heading change |
| `+0.6` | `-0.6` | Rotate in place |
| `+0.6` | `+0.3` | Curve toward the slower side |
| `0.0` | `0.0` | Decelerate toward rest in this model |
