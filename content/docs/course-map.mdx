# Course map

The course moves from architectural understanding to executable evidence.

| Module | Outcome | Evidence students produce | Build status |
|---|---|---|---|
| 01. Controller layers | Explain where hardware, Linux, HAL, WPILib, and team code belong | Layer map and signal trace | Complete first edition |
| 02. WPILib foundations | Recognize robot modes, periodic execution, and project structure | Lifecycle trace | Next to build |
| 03. Java robot code | Turn requirements into small, testable behavior | Java behavior change | Planned |
| 04. Driver Station | Separate operator input, mode control, and application state | Input-to-output trace | Planned |
| 05. CAN and devices | Distinguish configuration apps, Java libraries, firmware, and the bus | Device responsibility matrix | Planned |
| 06. NetworkTables and telemetry | Publish useful state without confusing presence with validity | Timestamped telemetry view | Planned |
| 07. Desktop simulation | Integrate robot behavior with simulated inputs, outputs, and physics | Reproducible simulation run | Planned |
| 08. Automated testing | Verify decision logic without physical hardware | Passing and deliberately failing JUnit tests | Planned |
| 09. Autonomous behavior | Compose bounded autonomous actions and stop them predictably | Short tested routine | Planned |
| 10. Vision inputs | Treat a camera result as a timestamped observation | Stale-target fallback | Planned |
| 11. Systemcore hardware | Compare software assumptions with a bounded bench test | Measured limitations and corrections | Planned |

## Language policy

Java receives the full reference implementation, tests, simulation, telemetry, CI, and eventual hardware validation first.

C++ and Python/RobotPy pages are added when a real difference exists in APIs, tooling, packaging, deployment, simulation, vendor support, or controller compatibility. We will not duplicate every Java lesson simply to claim three-language coverage.

## How each practical lesson will work

1. Read the system boundary.
2. Predict the result.
3. Modify a small piece of Java code.
4. Run the automated checks.
5. Run the WPILib simulation.
6. Inspect the named telemetry.
7. Introduce a controlled fault.
8. Diagnose and restore the baseline.

The layer lessons come first because students need a reliable mental model before they can diagnose code, network, device, or hardware failures.
