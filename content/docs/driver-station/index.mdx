# Module 04: Driver Station

The Driver Station is an operator console, communications endpoint, status display, and permission controller. It is not the robot program, the dashboard, NetworkTables, or an electrical disconnect.

## Module outcome

You will read the 2027 FIRST Driver Station as a set of independent signals, diagnose the first failed boundary, and trace one gamepad value into the Java behavior core without confusing connectivity with readiness.

## Readiness is a conjunction

For this module’s teleop scenario, readiness requires every condition below:

```text
radio reachable
AND robot reachable
AND UDP connected
AND TCP connected
AND robot code running
AND gamepad present
AND enabled
AND teleop selected
```

One green indicator cannot substitute for the others. A robot can answer a ping while team code is stopped. Team code can run while the gamepad is missing. Every connection can be healthy while the robot remains disabled.

## Executable diagnosis

The Java artifact now includes eight Driver Station status checks in addition to the nine behavior checks:

```bash
npm run test:java
```

Expected result:

```text
PASS: 17 Java behavior and Driver Station checks
```

The model diagnoses the first failed boundary. It does not emulate the FIRST Driver Station protocol or replace the official application.
